# Безопасность CodeTether

Модель угроз: приложение хранит пароль сервера OpenCode, который даёт полный доступ к агенту
на компьютере (выполнение команд). Компрометация пароля = компрометация машины.

## Что закрыто в 1.2.0

| # | Проблема | Было | Стало |
|---|---|---|---|
| 1 | Перенастройка на чужой сервер через intent/deep link | Любое приложение или ссылка могли записать `lan`/`wan`/`password` и приложение сразу отправляло пароль новому хосту | Перед применением — **диалог подтверждения** с показом адресов |
| 2 | Пароль уходил любому хосту, запросившему Basic-авторизацию | `onReceivedHttpAuthRequest` отдавал пароль без проверки | Пароль отдаётся **только** если хост совпадает с настроенным LAN/WAN (`isTrustedHost`) |
| 3 | Тихий откат к незашифрованному хранилищу | При сбое Keystore пароль писался в обычный `SharedPreferences` | При сбое Keystore пароль **не сохраняется** — только в памяти до перезапуска |
| 4 | WebView: доступ к файлам/контенту | Не было явных запретов (на API 26–29 `allowFileAccess` = true) | `allowFileAccess=false`, `allowContentAccess=false`, `allowFileAccessFromFileURLs=false`, `allowUniversalAccessFromFileURLs=false`, `setSaveFormData(false)`, `setGeolocationEnabled(false)` |
| 5 | Резервные копии | `allowBackup=true` (секреты исключены правилами) | `allowBackup=false` |
| 6 | QR-код содержит пароль | Молча | Скрипт настройки предупреждает: QR — секрет, не публиковать |

## Что осталось (сознательные компромиссы)

| # | Риск | Почему оставлено | Как снизить |
|---|---|---|---|
| A | Пароль передаётся по HTTP (Basic) в локальной сети | Домашняя сеть доверенная, а Tailscale уже шифрует | Включить HTTPS в tailnet (`tailscale serve` + HTTPS Certificates) и использовать `https://…ts.net` |
| B | QR-код содержит пароль в открытом виде | Простота онбординга | Не показывать QR посторонним; в 1.2.x планируется заменить пароль в QR на одноразовую ссылку `opencode pair` |
| C | `REQUEST_INSTALL_PACKAGES` | Нужно для автообновления | Android спрашивает разрешение; обновление принимается только с той же подписью |
| D | Экспортированная активность | Нужна для запуска и deep link | Закрыто подтверждением (п.1) |

## Проверено

- Пароль и заголовок `Authorization` не попадают в логи сервера (проверено поиском по `opencode.log`).
- `addJavascriptInterface` не используется — моста из веб-страницы в нативный код нет.
- Ключ подписи релиза (RSA 4096) не хранится в git; подпись проверяется при установке обновлений.
- Секреты исключены из резервного копирования (и теперь backup отключён целиком).

## Как проверить самостоятельно

1. Установить релиз, задать сервер через QR.
2. Из терминала попробовать перенастроить приложение на чужой адрес:
   ```bash
   adb shell am start -n dev.codetether/.MainActivity \
     --es lan "http://example.com" --es password "test"
   ```
   Ожидаемо: появляется диалог подтверждения; при отмене настройки не меняются.
3. Открыть в браузере `codetether://setup?d=<payload>` — тоже должен быть диалог.
4. На сервере смотреть, что пароль не уходит на `example.com`:
   ```bash
   sudo tcpdump -i any -A port 80 | grep -i authorization
   ```
