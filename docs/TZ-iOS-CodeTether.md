# CodeTether для iOS / iPadOS — описание продукта и требования

| | |
|---|---|
| Версия документа | 2.0 |
| Дата | 23.11.2026 |
| Статус | для команды iOS |
| Референс | Android-клиент CodeTether 1.3.0 |
| Платформа | iOS / iPadOS (версии и способ сборки — на усмотрение команды) |

---

## 1. Что это

**CodeTether** — мобильный клиент к серверу **OpenCode**, который работает на компьютере
пользователя. Приложение не содержит собственного чата и не дублирует логику OpenCode:
оно открывает его веб-интерфейс на планшете или телефоне так, чтобы этим было удобно
пользоваться каждый день.

Проще говоря: на компьютере запущен OpenCode, а CodeTether — это «пульт» к нему.
Все сессии, модели, файлы и история живут на компьютере; приложение только показывает
интерфейс и обеспечивает связь с сервером.

## 2. Какую проблему решает

Веб-интерфейс OpenCode открывается в браузере, но в повседневном использовании с iPad
это неудобно:

- адрес сервера меняется: дома один (локальная сеть), вне дома другой (Tailscale);
- каждый раз нужно вводить пароль и помнить, какой адрес сейчас рабочий;
- после обновления сервера браузер может показать старый интерфейс с «битыми» файлами;
- внешние ссылки открываются внутри чата, файлы не скачиваются нормально;
- клавиатура и системные жесты ведут себя не как в приложении.

CodeTether берёт это на себя: один раз настраивается — дальше открывается и работает
и дома, и снаружи.

## 3. Для кого

Владелец компьютера с OpenCode, который работает с ним с iPad (основной сценарий)
или iPhone. Один пользователь, один или несколько серверов, несколько устройств.

Не предполагается: многопользовательская работа, командный доступ, публичный сервис.

## 4. Как это работает

```
┌──────────────────────┐        LAN: http://192.168.x.x:49374
│  iPad / iPhone       │ ─────────────────────────────────────┐
│  CodeTether          │                                      ▼
│                      │        WAN: http://100.x.y.z:49374   ┌──────────────────┐
│  ─ показывает Web UI │ ───────────────────────────────────▶ │  Компьютер       │
│  ─ хранит адреса     │        (Tailscale)                   │  opencode serve  │
│  ─ авторизует        │                                      │  сессии, файлы   │
└──────────────────────┘                                      └──────────────────┘
```

1. На компьютере запущен `opencode serve` — HTTP-сервер с веб-интерфейсом и API.
   Обычно он слушает порт **49374**.
2. Сервер защищён паролем (HTTP Basic). Пароль задаётся при настройке сервера.
3. Дома компьютер доступен по локальному адресу (LAN). Вне дома — по адресу Tailscale (WAN).
   Tailscale — отдельное приложение на компьютере и на iPad; CodeTether только использует
   выданный адрес.
4. CodeTether хранит оба адреса и пароль. При запуске проверяет, какой адрес отвечает,
   и открывает веб-интерфейс с рабочего.
5. Все сессии и история хранятся на сервере. Поэтому переключение LAN ⇄ WAN не теряет
   открытый чат — после переключения страница просто загружается заново с сервера.

Установка и настройка сервера выполняются на компьютере скриптом
`scripts/setup-server.sh`: он включает сервер, задаёт пароль, настраивает Tailscale
и печатает QR-код для приложения.

## 5. Основные понятия

| Понятие | Что это |
|---|---|
| Сервер | `opencode serve` на компьютере пользователя |
| LAN | адрес сервера в домашней сети, например `http://192.168.31.39:49374` |
| WAN | адрес сервера через Tailscale, например `http://100.104.12.20:49374` |
| Пароль сервера | общий секрет для доступа к интерфейсу и API |
| Версия сервера | версия OpenCode, которую отдаёт сервер (например, `2.3.2`) |
| QR настройки | код, в котором зашиты LAN, WAN и пароль |
| Сессия | чат/задача в OpenCode, хранится на сервере |

## 6. Пользовательские сценарии

### 6.1. Первый запуск

Пользователь открывает приложение впервые. Показывается короткое объяснение и два пути:
**«Сканировать QR»** или **«Ввести адрес вручную»**. Без настроек приложение не пытается
открыть интерфейс — сначала нужно указать сервер.

### 6.2. Настройка по QR

На компьютере выполнен скрипт настройки, на экране — QR. Пользователь наводит камеру,
приложение показывает, какие адреса будут сохранены и что будет сохранён пароль.
После подтверждения — подключение и открытие интерфейса.

### 6.3. Настройка вручную

Пользователь вводит LAN и/или WAN адрес и пароль. Приложение проверяет, что сервер
отвечает, и открывает интерфейс.

### 6.4. Дома

Приложение проверяет локальный адрес и открывает его. Работает быстро, без интернета
(достаточно локальной сети).

### 6.5. Вне дома

Локальный адрес недоступен → приложение переключается на адрес Tailscale и открывает
тот же интерфейс. Пользователь видит в шапке, что работает через WAN.

### 6.6. Возвращение домой

Приложение периодически проверяет локальный адрес и, когда он снова доступен,
переключается обратно на LAN.

### 6.7. Сервер обновился

Сервер сообщает новую версию. Приложение обновляет интерфейс так, чтобы не остался
старый экран с несуществующими файлами: перезагружает страницу и очищает локальные
данные веб-интерфейса. Пользователь просто видит новую версию.

### 6.8. Скачивание файла

Пользователь нажимает на файл в чате — файл скачивается с авторизацией и сохраняется
на устройство (в «Файлы» или через меню «Поделиться»).

### 6.9. Внешняя ссылка

Ссылка на внешний сайт открывается в браузере, а не внутри приложения. Ссылки,
открывающиеся в новой вкладке, тоже уходят в браузер.

### 6.10. Ошибка

Сервер недоступен, пароль неверный, сеть пропала — приложение показывает понятную
причину и кнопку «Повторить», а не пустой экран.

## 7. Функции

### 7.1. Обязательные (первая версия)

### 7.2. Желательные (следующая версия)

| № | Функция | Комментарий |
|---|---|---|
| F-19 | Сканирование QR и deep link | Входит в первую версию как способ настройки; здесь — приём ссылки из мессенджера |
| F-20 | Поиск сервера в локальной сети | Автоматически найти OpenCode в сети и предложить подключиться |
| F-21 | Нативный список сессий | Список чатов с заголовком, проектом, моделью и временем; тап открывает сессию |
| F-22 | Уведомления о завершении задач | Сообщить, когда задача в OpenCode завершилась успешно или с ошибкой |
| F-23 | Проверка обновлений приложения | Сообщить о новой версии и предложить обновиться доступным способом |

> F-22 может быть ограничена платформой (фоновая работа). Команда iOS оценивает
> реализуемость и предлагает вариант; продуктовая цель — «пользователь узнаёт
> о завершении задачи, даже если приложение не открыто».

### 7.3. Не входит

- Собственный чат, свой рендер сообщений, свои модели.
- Свой сервер, синхронизация между устройствами, облако.
- Встроенный VPN/Tailscale-клиент.
- Многопользовательский доступ и роли.
- Публичный хостинг.

## 8. Экраны

### 8.1. Онбординг

Заголовок, 2–3 предложения о том, что нужно настроить сервер, две кнопки:
«Сканировать QR» и «Ввести вручную». Ссылка на инструкцию по настройке сервера.

### 8.2. Основной экран

Веб-интерфейс OpenCode на весь экран. Сверху — компактная панель:

- статус: `LAN · адрес`, `WAN · адрес`, `offline`;
- переподключить;
- переключить LAN/WAN;
- настройки;
- сканировать QR (если ещё не настроено или нужно сменить сервер).

Панель не должна мешать интерфейсу: минимум элементов, тёмный фон.

### 8.3. Настройки

- LAN-адрес, WAN-адрес.
- Пароль сервера.
- Таймаут проверки (для медленных сетей).
- «Сканировать QR».
- «Очистить кэш», «Очистить cookies».
- «О приложении».

### 8.4. «О приложении»

Версия приложения, текущий адрес, версия OpenCode, кнопка проверки обновлений.

### 8.5. Сканер QR

Камера с рамкой, подсказка «Наведите на QR из скрипта настройки». Незнакомый код —
сообщение, настройки не меняются.

### 8.6. Ошибки

Экран с причиной («сервер не отвечает», «неверный пароль», «нет сети») и действиями:
«Повторить», «Настройки». Без технических стектрейсов.

## 9. Требования к поведению

### 9.1. Проверка сервера

- Приложение периодически проверяет доступность адреса запросом к `/api/info`.
- Ответ `401` тоже означает, что сервер жив (просто нужен пароль).
- Проверка не должна заметно тормозить интерфейс и расходовать батарею.

### 9.2. Переключение маршрута

- LAN приоритетнее WAN.
- Переключение происходит автоматически, без перезапуска приложения.
- Если оба адреса недоступны — статус «offline» и повтор по кнопке/автоматически.
- Частые «прыжки» между адресами недопустимы (антидребезг).

### 9.3. Актуальность интерфейса

- После обновления сервера пользователь видит новую версию интерфейса.
- Старый интерфейс не должен возвращаться после перезапуска приложения.
- Очистка локальных данных не должна затрагивать настройки и пароль.

### 9.4. Авторизация

- Пароль вводится один раз и хранится безопасно.
- Пароль отправляется только настроенным адресам (LAN/WAN), не любым сайтам,
  которые могут открыться внутри интерфейса.
- При смене сервера (QR, ссылка, ручной ввод) — подтверждение пользователя.

### 9.5. Файлы

- Скачивание файлов из интерфейса работает с авторизацией.
- Пользователь видит прогресс или уведомление о начале загрузки.
- Большие файлы не должны ронять приложение.

### 9.6. Ссылки

- Внешние ссылки — в системном браузере.
- Внутренние ссылки сервера — внутри приложения.

### 9.7. Клавиатура

- При фокусе на поле ввода оно остаётся видимым над клавиатурой.
- Работает в портрете и ландшафте, с внешней клавиатурой и без.

### 9.8. Состояние

- Поворот экрана и переключение размера окна не сбрасывают открытую страницу.
- Уход приложения в фон и возврат не должны приводить к потере сессии
  (сессия хранится на сервере; допускается перезагрузка страницы).

### 9.9. Языки и тема

- Русский и английский интерфейс приложения.
- Тёмная и светлая темы; тёмная — основная, как в Android-версии.

## 10. Взаимодействие с сервером

Это контракт с сервером OpenCode; он одинаков для Android и iOS.

### 10.1. Авторизация

HTTP Basic: логин `opencode`, пароль — пароль сервера.

### 10.2. Используемые запросы

| Запрос | Назначение |
|---|---|
| `GET /api/info` | проверка доступности и версия сервера |
| `GET /api/session` | список сессий (для нативного списка) |
| `GET /api/event` | поток событий (для уведомлений) |
| `GET /?v=<версия>` | страница веб-интерфейса |
| `GET /_assets/*` | файлы интерфейса |

Пример ответа `/api/info`:

```json
{"version":"2.3.2","pid":3796,
 "urls":["http://127.0.0.1:49374","http://192.168.31.39:49374"],
 "paths":{"tmp":"/tmp/opencode"},
 "capabilities":{"persistentPty":true}}
```

### 10.3. QR-код и ссылка настройки

```
codetether://setup?d=<base64url(JSON)>
```

JSON:

```json
{"lan":"http://192.168.31.39:49374",
 "wan":"http://100.104.12.20:49374",
 "password":"…"}
```

`lan` и `wan` опциональны, но хотя бы один обязателен. Пароль опционален, если меняется
только адрес.

## 11. Ограничения и допущения

- На компьютере должен быть установлен и запущен OpenCode.
- Для доступа вне дома нужен Tailscale на компьютере и на устройстве.
- Сервер обычно работает по HTTP в локальной сети/Tailscale; вопросы защищённых
  соединений и политик платформы команда iOS решает сама.
- Все данные (сессии, файлы, история) хранятся на сервере; приложение не является
  источником истины.
- Приложение не заменяет веб-интерфейс: если OpenCode добавит новую функцию в веб,
  она появится и в приложении.
- Уведомления в фоне зависят от возможностей платформы; команда оценивает и предлагает
  решение (см. F-22).

## 12. Критерии приёмки

Приложение считается готовым, если пользователь может:

1. Установить приложение, отсканировать QR и открыть чат — без инструкций извне.
2. Настроить сервер вручную, если QR нет.
3. Дома работать по LAN, а выйдя из дома — автоматически продолжить по WAN.
4. Вернуться домой и снова работать по LAN без ручных действий.
5. Переключить адрес вручную и переподключиться.
6. Открыть свои сессии, отправить сообщение, скачать файл.
7. Открыть внешнюю ссылку — она открывается в браузере.
8. После обновления сервера увидеть новый интерфейс, а не старый/битый.
9. Понять, что случилось, если сервер недоступен или пароль неверный.
10. Пользоваться с клавиатурой, в портрете и ландшафте, в Split View.
11. Сменить тему и язык.
