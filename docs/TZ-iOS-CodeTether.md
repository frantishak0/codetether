## 1. Общие сведения

**CodeTether** — неофициальный клиент к серверу [OpenCode](https://opencode.ai), запущенному
на компьютере пользователя. Приложение не содержит собственного чата: оно открывает
веб-интерфейс OpenCode в `WKWebView` и решает всё, что браузер на планшете делает плохо:

- находит сервер в локальной сети и/или через Tailscale;
- автоматически выбирает рабочий маршрут (LAN быстрее, WAN работает откуда угодно);
- авторизует WebView по HTTP Basic, не отдавая пароль посторонним хостам;
- переживает обновления сервера без «залипшего» старого интерфейса;
- скачивает файлы, открывает внешние ссылки в Safari, держит нормальный ввод с клавиатуры.

Продукт личный/командный: распространяется через TestFlight или прямую подпись, не через
App Store (см. §12).

### 1.1. Аудитория

Владелец компьютера с OpenCode, работающий с ним с iPad/iPhone: дома по Wi-Fi, вне дома —
через Tailscale. Один пользователь, несколько устройств, один сервер (возможны несколько).

## 2. Термины

| Термин | Значение |
|---|---|
| OpenCode server | `opencode serve`, HTTP-сервер на компьютере, по умолчанию порт **49374** |
| LAN | адрес сервера в домашней сети, например `http://192.168.31.39:49374` |
| WAN | адрес сервера через Tailscale, например `http://100.104.12.20:49374` или `http://host.tailnet.ts.net:8443` |
| Web UI | веб-интерфейс OpenCode, который сервер отдаёт на `/` |
| Версия сервера | значение `version` из `GET /api/info`, например `2.3.2` |
| Setup payload | `codetether://setup?d=<base64url(JSON)>`, JSON: `{"lan":"…","wan":"…","password":"…"}` |
| Доверенный хост | host из настроенных LAN/WAN — только ему отправляется пароль |

## 3. Цели и объём

### 3.1. Цели MVP

1. Открыть веб-интерфейс OpenCode на iPad без браузера и без ручного ввода адреса каждый раз.
2. Автоматически работать и дома, и снаружи — без действий пользователя.
3. Не терять доступ после обновления сервера и не показывать «залипший» старый UI.
4. Безопасно хранить пароль и не отдавать его произвольным хостам.

### 3.2. Входит в объём

- Первичная настройка вручную и по QR/deep link.
- Проверка доступности LAN/WAN, автопереключение, ручное переключение.
- `WKWebView` с Basic-авторизацией, версионированным URL и сбросом кэша при обновлении сервера.
- Загрузка файлов из Web UI.
- Внешние ссылки — в Safari.
- Настройки, «О приложении», локализация (ru/en), тёмная тема.
- Поведение при потере сети, 401, таймауте, обновлении сервера.
- iPad-раскладка: Split View / Stage Manager / поворот без потери состояния.
- Клавиатура не перекрывает поле ввода.

### 3.3. Не входит в MVP

- Собственный чат/рендер сообщений (используется Web UI).
- Фоновые push-уведомления о завершении задач (нужен APNs и серверная часть) — Phase 3.
- Встроенный Tailscale/VPN-клиент (пользователь ставит приложение Tailscale отдельно).
- Собственный сервер/gateway, синхронизация между устройствами.
- Android-паритет по самообновлению APK — на iOS невозможно, см. §12.

## 4. Пользовательские сценарии

### US-1. Первый запуск

Пользователь устанавливает приложение, открывает. Показывается онбординг: «Сканировать QR»,
«Ввести адрес вручную», ссылка на инструкцию по настройке сервера. Без настроек WebView не грузится.

### US-2. Настройка по QR

На компьютере выполнен `scripts/setup-server.sh`, он печатает QR. Пользователь сканирует его
камерой. Приложение показывает подтверждение: какие адреса и что будет сохранён пароль.
После подтверждения — подключение и открытие Web UI.

### US-3. Настройка вручную

Пользователь вводит LAN и/или WAN адрес и пароль сервера. Приложение проверяет доступность
и открывает интерфейс.

### US-4. Дома

Приложение проверяет LAN (быстро), открывает его. Раз в минуту проверяет, не вернулся ли LAN,
если сейчас работает через WAN.

### US-5. Вне дома

LAN недоступен → приложение переключается на WAN (Tailscale) и открывает тот же интерфейс.
Пользователь видит статус «WAN · <адрес>».

### US-6. Сервер обновился

Сервер ответил новой версией в `/api/info`. Приложение сбрасывает данные WebView, открывает
`/?v=<новая версия>` и показывает свежий интерфейс. Старый интерфейс не возвращается.

### US-7. Скачивание файла

Пользователь нажимает на файл в чате. Файл скачивается с авторизацией и сохраняется
в «Файлы» (или открывается share sheet).

### US-8. Внешняя ссылка

Ссылка на внешний сайт открывается в Safari, а не внутри WebView. `target="_blank"` работает.

### US-9. Ошибка

Нет сети / сервер недоступен / неверный пароль — понятный экран с причиной и кнопкой
«Повторить». Пароль неверный — предложение открыть настройки.

## 5. Функциональные требования

### FR-01. Онбординг и хранение настроек

- При первом запуске нет адресов → показывается онбординг, WebView не загружается.
- Настройки: `lan`, `wan` (могут быть пустыми, но не оба), `password`, `probeTimeout` (по умолчанию 1200 мс).
- Пароль хранится только в **Keychain** (`kSecClassGenericPassword`, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`), не в `UserDefaults`.
- Нормализация URL: обрезать пробелы и `/`, требовать схему `http`/`https`, отклонять иные.

**Приёмка:** после переустановки приложения настройки отсутствуют; после перезапуска — сохраняются;
пароль не виден в логах и в бэкапе (Data Protection).

### FR-02. Проверка доступности (probe)

- `GET <base>/api/info`, таймаут 1.2 с (настраиваемый), без редиректов.
- Ответ **200** или **401** считается доступностью (401 = сервер жив, нужен пароль).
- Ответ с `version` сохраняется как версия сервера.
- Параллельная проверка LAN и WAN; LAN имеет приоритет.

**Приёмка:** при выключенном сервере probe завершается ≤ 1.5 с и не блокирует UI.

### FR-03. Выбор маршрута и автопереключение

- Если LAN доступен — используется LAN.
- Иначе, если WAN доступен — WAN.
- Если ничего — статус «offline», кнопка «Повторить», WebView показывает последнее состояние/ошибку.
- При работе через WAN раз в 60 с проверяется LAN; при возврате LAN — переключение.
- Антидребезг: не переключаться чаще одного раза в 30 с; не перезагружать страницу при
  проверке, если адрес не изменился.

**Приёмка:** сценарий «вышли из дома / вернулись» переключает маршрут без участия пользователя
и без потери открытой сессии (сессия живёт на сервере).

### FR-04. Ручное управление

- Кнопка «Переподключить»: probe + перезагрузка текущего адреса.
- Кнопка «LAN ⇄ WAN»: принудительное переключение на второй адрес; если он пуст — сообщение.
- Статус в шапке: `LAN · <url>`, `WAN · <url>`, `offline`, `manual · <url>`.

### FR-05. WebView и авторизация

- `WKWebView` на весь экран под шапкой.
- Basic-авторизация: в `didReceive challenge` для `NSURLAuthenticationMethodHTTPBasic`
  отправлять `URLCredential(user: "opencode", password: <Keychain>, persistence: .none)`
  **только если host входит в доверенные** (LAN/WAN). Иначе — `cancelAuthenticationChallenge`.
- Пароль не логировать, не показывать, не передавать в URL.
- `javaScriptEnabled`, `domStorageEnabled`; доступ к локальным файлам не предоставлять
  (никаких `loadFileURL`, `allowFileAccess`-аналогов).
- Тёмный фон под страницей, чтобы не было белой вспышки при загрузке.

**Приёмка:** при верном пароле открывается UI; при неверном — сообщение, пароль не отправляется
на сторонний хост (проверить запросом на тестовый сервер).

### FR-06. Версия сервера и кэш

- Документ всегда грузится как `<base>/?v=<serverVersion>` (версия из `/api/info`).
- При смене версии сервера:
  1. остановить/очистить WebView;
  2. удалить данные: `WKWebsiteDataStore.default().removeData(ofTypes: allWebsiteDataTypes, modifiedSince: .distantPast)`;
  3. очистить `URLCache` и cookies;
  4. загрузить `/?v=<newVersion>`.
- Перед очисткой — попытаться `navigator.serviceWorker.getRegistrations()` + `unregister()`
  и `caches.keys()` + `delete()` через `evaluateJavaScript` (для https-оригинов).
- На http-оригине Service Worker недоступен — это нормально.

**Приёмка:** после обновления сервера (2.x → 2.y) приложение показывает новый UI,
в консоли нет 404 на `/_assets/*`; старый интерфейс не возвращается после перезапуска.

### FR-07. Внешние ссылки и `target="_blank"`

- Навигация на другой host → `UIApplication.shared.open(url)` (Safari), WebView не уходит.
- `target="_blank"` → `WKUIDelegate.createWebViewWith` → открыть системно.
- `mailto:`, `tel:`, `intent:` — системно.

### FR-08. Загрузка файлов

- `WKDownload` (iOS 14.5+) + `WKDownloadDelegate`.
- Авторизация: Basic-креды для доверенного хоста.
- Сохранение: временный файл → `UIActivityViewController` («Сохранить в Файлы», «Поделиться»).
- Индикатор прогресса/тост «Скачивается <имя>».

**Приёмка:** файл из чата скачивается и открывается в «Файлах»; большие файлы (>50 МБ)
не роняют приложение.

### FR-09. QR и deep link

- Сканер: `AVCaptureSession`, только область QR, разрешение `NSCameraUsageDescription`.
- Поддержка `codetether://setup?d=<base64url(JSON)>` и вставки JSON.
- Перед применением — **обязательное подтверждение**: показать LAN/WAN и предупреждение,
  что пароль будет сохранён и отправляться только этим хостам.
- Незнакомый QR — сообщение, ничего не менять.
- Схема регистрируется в `CFBundleURLTypes`.

**Приёмка:** QR из `setup-server.sh` настраивает приложение за один скан; подменённый QR
без подтверждения ничего не меняет.

### FR-10. Поиск сервера в локальной сети (Phase 2)

- `NWBrowser` для `_http._tcp` (Bonjour), `NSBonjourServices` + `NSLocalNetworkUsageDescription`.
- Кандидаты проверяются через `/api/info`; показывается список «имя — адрес — версия».
- Выбор → подтверждение → сохранение как LAN.

### FR-11. Нативный список сессий (Phase 2)

- `GET /api/session` (Basic), поля: `id`, `title`, `location.directory`, `time.updated`, `model`.
- Список с поиском и сортировкой по времени; тап открывает Web UI.
- Ограничение: прямых deep link на сессию в Web UI нет — открывается корень/список.

### FR-12. Уведомления о задачах (Phase 3, вне MVP)

- На iOS фоновое SSE невозможно: приложение в фоне живёт секунды.
- Требуется APNs + серверный компонент, который слушает `session.execution.succeeded/failed`
  и отправляет push.
- До реализации — только индикация внутри открытого приложения.

### FR-13. «О приложении»

- Версия приложения и сборки, текущий адрес, версия OpenCode, кнопка «Проверить обновления».
- Обновление: открыть TestFlight/App Store (см. §12), не скачивать бинарник самостоятельно.

### FR-14. Локализация и тема

- Русский и английский; строки в `Localizable.xcstrings`.
- Тёмная и светлая темы, семантические цвета; тёмная шапка как в Android-версии.
- RTL не обязателен, но использовать системные компоненты.

### FR-15. Клавиатура

- Поле ввода Web UI не должно перекрываться клавиатурой.
- Использовать `keyboardLayoutGuide` / safe area insets; проверить в портрете и ландшафте,
  на iPad с внешней клавиатурой и без.

## 6. Экраны и UI (HIG)

### 6.1. Структура

Максимум два уровня навигации. Предлагаемая оболочка:

```
TabView(.sidebarAdaptable)            // на iPad — сайдбар
├── «Сессии»   NavigationStack → WebView
├── «Настройки» NavigationStack → форма
└── «О приложении» (можно внутри настроек)
```

Для MVP достаточно двух разделов: **Сессии** (WebView) и **Настройки**. «О приложении» —
секция внутри настроек.

### 6.2. Шапка

- Статус: `LAN · http://…`, `WAN · http://…`, `offline`.
- Кнопки: переподключить (`arrow.clockwise`), переключить LAN/WAN (`arrow.left.arrow.right`),
  настройки (`gearshape`), сканировать QR (`qrcode.viewfinder`).
- На iPad — toolbar в `NavigationStack`, не самодельная панель.

### 6.3. Настройки (Form)

- LAN URL, WAN URL, пароль (SecureField), таймаут.
- «Найти сервер в сети» (Phase 2), «Сканировать QR».
- «Очистить кэш» (сброс WebView), «Очистить cookies».
- «О приложении»: версия, сервер, версия OpenCode.

### 6.4. Онбординг

- Заголовок, короткое объяснение, две кнопки: «Сканировать QR» и «Ввести вручную».
- Ссылка «Как настроить сервер» (открыть инструкцию в Safari).

### 6.5. HIG-требования

- iPad-first, но работает и на iPhone.
- Размеры шрифтов — системные text styles, Dynamic Type обязателен.
- Хит-зоны ≥ 44×44 pt.
- Тёмная тема, контраст ≥ 4.5:1.
- VoiceOver: подписи кнопок и статуса, логичный порядок фокуса.
- Модальные окна — page/form sheet, не full screen.
- Split View / Stage Manager: WebView занимает доступную область, настройки — sheet.

## 7. Архитектура

### 7.1. Стек

- Swift 6, SwiftUI, Observation (`@Observable`), async/await.
- `WKWebView` через `UIViewRepresentable` (`WebViewContainer`).
- `URLSession` для probe/API.
- Keychain (обёртка `KeychainStore`).
- `NWBrowser` (Bonjour), `AVFoundation` (QR), `WKDownload`.
- Без сторонних зависимостей; XcodeGen (`project.yml`) как источник истины, `.xcodeproj` не коммитить.

### 7.2. Структура проекта

```
CodeTether/
├── project.yml
├── Sources/
│   ├── App/CodeTetherApp.swift
│   ├── Navigation/RootView.swift
│   ├── Features/
│   │   ├── Browser/  (WebView, BrowserViewModel, шапка)
│   │   ├── Settings/ (SettingsView, SettingsViewModel)
│   │   ├── Onboarding/
│   │   └── Scanner/
│   ├── Core/
│   │   ├── Models/ (ServerConfig, ServerInfo, Route)
│   │   ├── Networking/ (ProbeClient, APIClient)
│   │   ├── Security/ (KeychainStore, TrustedHosts)
│   │   ├── Discovery/ (BonjourBrowser) [Phase 2]
│   │   └── Design/
│   └── Resources/
└── Tests/
```

### 7.3. Состояние

```swift
@MainActor @Observable
final class BrowserViewModel {
    enum Route { case lan, wan, offline }
    var status: Route = .offline
    var baseURL: URL?
    var serverVersion: String?
    var isLoading = false
    var error: String?

    func connect(force: Bool) async { … }   // probe → выбор → загрузка
    func switchRoute() async { … }
    func reload() async { … }
}
```

- Один `BrowserViewModel` на приложение (или на сцену).
- `WebViewContainer` не пересоздаётся при смене статуса; URL меняется через `load(URLRequest)`.
- При смене версии сервера — очистка data store и новый `load`.

### 7.4. Потоки

- probe/API — `async` в фоне, UI-обновления на `@MainActor`.
- Автопереключение — `Task` с `Task.sleep`, отменяется при уходе в фон/смене адреса.
- Один probe-запрос не должен блокировать WebView.

## 8. Сетевой контракт

### 8.1. Авторизация

```
Authorization: Basic base64("opencode:" + password)
```

Отправляется только на доверенные хосты (LAN/WAN). 401 — валидный ответ для probe.

### 8.2. Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/info` | версия, pid, urls, paths, capabilities |
| GET | `/api/session` | список сессий (Phase 2) |
| GET | `/api/event` | SSE-события (Phase 3) |
| GET | `/?v=<version>` | HTML веб-интерфейса |
| GET | `/_assets/*` | статика UI (immutable, hashed) |

`/api/info` (пример):

```json
{"version":"2.3.2","pid":3796,"hostname":"…",
 "urls":["http://127.0.0.1:49374","http://192.168.31.39:49374"],
 "paths":{"tmp":"/tmp/opencode"},
 "capabilities":{"persistentPty":true}}
```

### 8.3. Setup payload

```
codetether://setup?d=<base64url(JSON)>
JSON: {"lan":"http://192.168.31.39:49374","wan":"http://100.104.12.20:49374","password":"…"}
```

Поля `lan`/`wan` опциональны, но хотя бы одно обязательно. Пароль опционален для сценария
«сменить только адрес».

### 8.4. Прочее

- OpenCode на LAN/Tailscale обычно работает по **http**; TLS не обязателен (см. ATS).
- Таймауты: probe 1.2 с; API 5 с; загрузка документа 10 с.
- User-Agent приложения: `CodeTether-iOS/<version>`.

## 9. Безопасность

| Требование | Реализация |
|---|---|
| Пароль | Keychain, `AfterFirstUnlockThisDeviceOnly`, не в UserDefaults/логах |
| Доверенные хосты | пароль только для host из настроек; иначе `cancelAuthenticationChallenge` |
| Смена сервера | подтверждение для QR/deep link/ручного ввода |
| WebView | без доступа к локальным файлам, без `loadFileURL` |
| ATS | см. §10.1; минимально необходимые исключения |
| Бэкапы | Keychain-элемент `ThisDeviceOnly`; пароль не попадает в iCloud-бэкап |
| Логи | не логировать Authorization, пароль, содержимое чатов |
| Скриншоты | не требуется скрывать (контент пользователя), но пароль в UI не показывать |
| Cookies | `WKHTTPCookieStore`; при смене сервера очищать |

Угрозы, которые закрываем: подмена адреса через QR/deep link → утечка пароля на чужой хост;
запрос Basic-авторизации от чужого сайта внутри WebView; чтение локальных файлов; утечка
пароля через бэкап/логи.

## 10. Ограничения платформы и конфигурация

### 10.1. ATS (App Transport Security)

LAN и Tailscale — обычно `http://`. Варианты:

- MVP: `NSAllowsArbitraryLoads = true` (плюс `NSAllowsLocalNetworking = true`), с пометкой
  в README, что это личное приложение для собственного сервера.
- Если нужен App Store: узкие исключения `NSExceptionDomains` для `ts.net` и
  `NSAllowsLocalNetworking`; проверить IP-литералы (ATS для IP-адресов может не применяться,
  но поведение зависит от версии iOS).

`Info.plist` (минимум):

```xml
<key>NSAppTransportSecurity</key>
<dict>
  <key>NSAllowsArbitraryLoads</key><true/>
  <key>NSAllowsLocalNetworking</key><true/>
</dict>
<key>NSLocalNetworkUsageDescription</key>
<string>CodeTether ищет сервер OpenCode в вашей сети.</string>
```

### 10.2. Локальная сеть

- iOS 14+ спрашивает разрешение на локальную сеть при первом обращении к LAN IP/Bonjour.
- Если пользователь отказал — показать объяснение и ссылку в Настройки.
- Без разрешения LAN-адреса недоступны; WAN (Tailscale) работает.

### 10.3. Tailscale

- Отдельное приложение Tailscale на iPad/iPhone, пользователь входит в свой tailnet.
- CodeTether не управляет туннелем; только использует адрес `100.x.y.z` / `*.ts.net`.
- Если Tailscale выключен — WAN-проверка падает, приложение остаётся на LAN/offline.

### 10.4. Фон и уведомления

- Фоновое SSE/WebSocket не живёт; после сворачивания соединения рвутся.
- Уведомления о завершении задач без APNs невозможны (Phase 3).
- Фоновое обновление контента не требуется.

### 10.5. Клавиатура

- WKWebView сам подстраивает visual viewport, но нужно проверить:
  - поле ввода не уходит под клавиатуру;
  - safe area снизу не даёт лишнего отступа;
  - при внешней клавиатуре (Magic Keyboard) поведение корректное.

## 15. Риски и открытые вопросы

| Риск | Влияние | Митигация |

## Приложение A. Уроки Android-версии (учесть заранее)

1. **Service Worker** веб-интерфейса отдаёт закэшированный `index.html` на любую навигацию
   и игнорирует `?v=`; `clearCache` его не удаляет. Решение: чистить `WKWebsiteDataStore`
   при смене версии сервера + снимать регистрацию SW через JS (для https-оригинов).
2. **Версия в URL** (`/?v=<version>`) обязательна — иначе HTTP-кэш может отдать старый документ.
3. **Клавиатура**: на Android окно не сжималось под IME (edge-to-edge); на iOS проверить
   `keyboardLayoutGuide` и safe area — не повторять ошибку.
4. **Старые WebView**: UI 2.3.x использует `URL.canParse`, `Promise.withResolvers`,
   `Map.groupBy`, `Array.fromAsync`, `Promise.try`. На iOS 18 всё есть; если снижать
   минимальную версию — добавить полифилы.
5. **Пароль только доверенным хостам** — иначе любой сайт в WebView может запросить Basic.
6. **Подтверждение смены сервера** для QR/deep link — защита от подмены адреса.
