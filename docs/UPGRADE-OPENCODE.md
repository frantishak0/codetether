# Апгрейд OpenCode 2.1.2 → 2.3.2

Ночной апгрейд основного сервера (порт 49374) и инстанса для Mac (порт 49375)
с бэкапом, health-check'ами и автоматическим откатом. Участие пользователя Mac
не требуется: его доступ идёт через тот же gateway/Funnel и восстанавливается сам.

## Что подготовлено

| Что | Где |
|---|---|
| Артефакт 2.3.2 + SHA256 | `~/oc-client/dist/opencode-2.3.2/` |
| Скрипт апгрейда | `~/oc-client/scripts/upgrade-opencode.sh` |
| systemd-сервис | `~/.config/systemd/user/oc-upgrade.service` |
| Таймер (03:30) | `~/.config/systemd/user/oc-upgrade.timer` |
| Бэкапы | `~/oc-client/dist/backups/opencode-2.1.2-<ts>/` |
| Отчёт о последнем прогоне | `~/oc-client/dist/upgrade-latest.txt` |
| История прогонов | `~/oc-client/dist/upgrade-history.log` |

Проверено заранее:

- бинарник 2.3.2 запускается на этой машине;
- 2.3.2 открывает **копию рабочей базы** и видит 50 сессий;
- схема базы не требует несовместимой миграции;
- `opencode service start/stop` и резервный запуск `serve --service` работают;
- перезапуск `oc-main` (Mac) поднимается за ~2 с, gateway и публичный Funnel живы;
- конфиг `snapshots: false` и `watcher.ignore` в 2.3.2 поддерживаются.

## Что произойдёт ночью

Таймер срабатывает в **03:30** (локальное время). Порядок:

1. Проверка окна: 01:00–06:59. Если таймер сработал с опозданием (ноутбук спал),
   скрипт выходит без изменений.
2. Проверка активности: если за последние 15 минут была активная сессия,
   апгрейд переносится (ничего не трогается).
3. Бэкап: консистентный снимок БД (`sqlite3 .backup` + `integrity_check`),
   бинарник 2.1.2 и конфиг.
4. Атомарная подмена бинарника (старый остаётся как `.bak-2.1.2`).
5. Перезапуск Mac-инстанса и основного сервиса.
6. Проверки: `2.3.2` на 49374, 49375, gateway 49377, публичный Funnel, bus 49376.
7. Если хоть одна проверка не прошла — **автоматический откат** на 2.1.2
   с восстановлением базы из бэкапа.
8. Отчёт в `upgrade-latest.txt` + уведомление на рабочем столе.

Простой: обычно 10–30 секунд. Mac-пользователь в этот момент может увидеть
кратковременную ошибку соединения; после перезапуска доступ возвращается сам,
повторный вход не нужен (токен не меняется).

## Инцидент 20.11 и исправление

Первый ночной прогон прошёл успешно (03:31, все проверки зелёные), но сразу после
завершения systemd-юнита основной сервис :49374 умер: `ExecStart` запускал его
внутри cgroup юнита, а systemd при завершении oneshot-юнита убивает оставшиеся
процессы группы. Mac-инстанс выжил, потому что он отдельный systemd-юнит.

Следствие: с 03:31 до 09:16 сервер :49374 был недоступен; планшет в 09:16 получил
503, пока сервис поднимался (это сделал открытый TUI).

Исправлено в `oc-upgrade.service`:

- `KillMode=none` — systemd больше не убивает процессы, запущенные из юнита;
- `ExecStopPost` — страховка: если порт :49374 всё равно не слушает, сервис
  поднимается ещё раз в конце.

Проверено контрольным тестом на изолированном порту 49996:
с `KillMode=none` сервис после завершения юнита жив, без него — умирает.

Остаточная хрупкость: основной сервис запускается из TUI и живёт, пока живёт
терминал. Если нужен полный автозапуск после перезагрузки — стоит завести
отдельный systemd-юнит для :49374 (как `oc-main` для :49375).

## Команды

```bash
# предпроверка (ничего не меняет)
~/oc-client/scripts/upgrade-opencode.sh --check

# состояние
~/oc-client/scripts/upgrade-opencode.sh --status

# выполнить сейчас (вручную)
~/oc-client/scripts/upgrade-opencode.sh --apply

# откат на 2.1.2 из последнего бэкапа
~/oc-client/scripts/upgrade-opencode.sh --rollback

# включить/выключить ночной таймер
systemctl --user enable --now oc-upgrade.timer
systemctl --user disable --now oc-upgrade.timer
systemctl --user list-timers oc-upgrade.timer
```

## Сторона Mac

Mac-клиент — Electron 26 (Chromium 116, август 2023). UI 2.3.2 использует API,
которых в нём нет, поэтому шлюз подготовлен заранее:

- в `/_polyfill.js` добавлены `Promise.withResolvers`, `Map.groupBy`,
  `Array.fromAsync`, `Promise.try` (проверены в Node с удалёнными встроенными);
- `/sw.js` в шлюзе уже подменяется на самоудаляющийся Service Worker,
  который чистит CacheStorage — старый интерфейс не залипнет;
- HTML отдаётся с `no-store`, полифил — с `no-store`, так что клиент
  гарантированно получит новую версию;
- `crossorigin` у module-скриптов убирается для старого WebKit.

Пользователю Mac ничего делать не нужно: адрес, токен и cookie не меняются.
Во время переключения (10–30 с) он может увидеть ошибку соединения — после
перезапуска всё вернётся само.

## Утро после апгрейда

```bash
cat ~/oc-client/dist/upgrade-latest.txt
~/oc-client/scripts/upgrade-opencode.sh --status
```

Ожидаемый отчёт:

```
OpenCode обновлён: 2.1.2 -> 2.3.2
сейчас: main=2.3.2 mac=2.3.2 gw=2.3.2
```

Если в отчёте `выполнен откат` — сервис уже работает на 2.1.2, разбираться
можно спокойно: лог лежит рядом (`dist/backups/upgrade-*.log`).

## Что учесть

- **База общая** у 49374 и 49375, поэтому бэкап делается один и один раз.
- **Откат** восстанавливает базу из снимка, сделанного до апгрейда: если между
  бэкапом и откатом кто-то успел создать сессию, она пропадёт. Ночью это
  несколько секунд.
- **TUI в терминале** (процесс `opencode`) остаётся на 2.1.2 до перезапуска —
  это только интерфейс, на сервер и планшет не влияет. Перезапустить можно утром.
- **CodeTether** при смене версии сервера сам делает полный сброс WebView и
  перезапускается (проверено в 1.2.9). Действий с планшетом не нужно.
- Бэкапов хранится 3 последних; старые удаляются автоматически.
