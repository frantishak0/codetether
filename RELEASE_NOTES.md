## CodeTether 1.2.9

### Причина найдена и проверена на планшете

Веб-интерфейс OpenCode регистрирует Service Worker (Workbox) с правилом
`NavigationRoute → /index.html`. Он отдаёт закэшированную оболочку приложения на
**любую** навигацию и **игнорирует query-строку**. Поэтому `/?v=2.1.2` из 1.2.6
до сервера не доходил — его перехватывал Service Worker.

`WebView.clearCache()` не удаляет CacheStorage и регистрации SW, а удаление
отдельных папок профиля не срабатывало, пока профиль держал процесс Chromium.
Старый `index.html` (2.1.1) жил в кэше, его файлы (`health-CWDW51F7.js`) на сервере
уже 404 — отсюда `TypeError: Failed to fetch`.

Скриншот ошибки это подтверждал: ассеты запрашивались по `https://…:8443`, хотя
8443 уже отдаётся только по HTTP — то есть документ был очень старым, ещё
с тех пор, когда там был HTTPS.

### Что сделано

- **Полный сброс профиля WebView** — удаляется весь `app_webview` (CacheStorage +
  Service Worker), только в новом процессе: при обновлении приложения, обновлении
  сервера и по кнопке «Сбросить кэш».
- **Service Worker нейтрализован**: `/sw.js` подменяется пустым SW, который сразу
  снимает себя с регистрации; после каждой загрузки страница дополнительно снимает
  регистрации и чистит CacheStorage.
- **Самовосстановление**: приложение читает фактическую версию интерфейса и текст
  ошибки. Если страница старая или показан `Failed to fetch` — автоматически
  перезагружает документ, после трёх неудач делает полный сброс и перезапускается.
- Версия сервера в URL документа (`/?v=2.1.2`) сохранена.
- Исправлена ошибка в самой проверке: `evaluateJavascript` не ждёт Promise,
  поэтому первая версия самовосстановления получала `{}` и не срабатывала.

### Проверено на устройстве (Lenovo TB710FU)

```
href=http://192.168.31.39:49374/?v=2.1.2
serverVer=2.1.2  controller=0 (Service Worker не управляет страницей)
swRegistrations=-2 (на HTTP-оригине SW вообще недоступен)
err=false
```

Интерфейс открывается свежим, сессии и проекты на месте.
